Decision

  • Pull from the registry explicitly and infrequently: before an event and when the offline dependency-input check reports a mismatch.
  • Source-only changes build offline against the last pinned compatible image. A changed Dockerfile/configuration or dependency manifest needs a compatible published image; an upstream CLI/base change needs a new pull and stays a manual check for existing images.
  • Never attempt a first dependency update without internet at an event. Keep the previous compatible source, image and ready overlay in a separate prepared workspace as a recovery set; a rebuild mutates its own workspace artifacts.
  • Local full-image builds and their compression/cache/USB-versus-reverse-SSH optimization questions leave the normal workflow. The legacy build/ship helper remains an emergency fallback when the registry cannot supply a compatible image.
