Colima hangs from agent-container DDS egress (2026-11-06)

Investigation · 2026-11-06 · Mac mini Colima VM, Jazzy, Fast DDS 2.14.6; no robot

Fixed by a VM guard plus off-by-default remote DDS and Foxglove. Not yet validated across colima stop/start (other agent containers were running), nor on a robot.

Symptom

Colima on the Mac mini hung twice (about 02:00 and 09:10). The VM journal shows virtio_net eth0: NETDEV WATCHDOG ... transmit queue 0 timed out for minutes, with no OOM; Docker and SSH, forwarded over that link, then died. VM egress goes through Lima's userspace NAT (limactl usernet): 151% CPU and 1.5 GB RSS during the first hang, 2.1 GB 32 minutes after a restart.

Cause

Bridged agent containers run the image's default Fast DDS profile (isaac_ros_common/docker/fastdds_cable.xml), whose initialPeersList holds the robots' Tailscale IPs with maxInitialPeersRange 32. Each participant sends SPDP unicast to every peer address and port in range. tcpdump on the VM eth0 saw 731k packets / 388 MB to 100.93.23.77 in about 30 minutes, and the NAT keeps state for each flow.

Guard (VM)

scripts/agent_container.sh installs /usr/local/sbin/thornbots-agent-guard and a thornbots-agent-guard.service unit in the Colima VM (tied to docker.service). It creates chain THORNBOTS-AGENT (-d 100.64.0.0/10 -j DROP), jumped to from DOCKER-USER for docker0 and br+; each step checks with iptables -C first so reruns add nothing. It is a unit, not Colima's provision list, because the unit lives on the VM disk (survives colima stop/start) and reruns after each Docker start when Docker recreates DOCKER-USER; up also reapplies it.

Opt-out leaks as expected.
up -T makes a dedicated bridge ta<cksum> that br+ does not match and sets THORNBOTS_REMOTE_DDS=true. Measured: 1440 packets to 100.64.0.0/10 on VM eth0 in 25 s from one ros2 topic pub, limactl usernet RSS 47 to about 99 MB within 6 s. Removed with the container.
Host-network containers bypass the guard.
UDP to 100.93.23.77:9998 from --network host reached VM eth0 (5 of 5); from a bridged container 0 of 5. Host-network traffic takes OUTPUT, not DOCKER-USER.
The guard has absorbed substantial traffic.
5.77M packets / 2.99 GB dropped since install. isaac-agent-t17rl (172.17.0.2), started before the switch existed, was still sending about 1,150 packets/s to Tailscale, all dropped; its launches pick up defaults when restarted.
Not covered or tested.
IPv6 (fd7a:115c:a1e0::/48) is not guarded because the peers list is IPv4 only. Not tested: a real colima stop/start (two other agent containers were running) and a robot.

Changes

isaac_ros_common (guard follow-up, THORNBOTS_* container env, up -F/-T, dexec.sh, bashrc), thornbots_pkg (remote_dds, fastdds_udp_only_local.xml, operator_workflow), sentry_localization (fastdds_no_shm_local.xml), sim (dds_switch.py, foxglove:=, remote_dds:=), isaac-ros-startup (THORNBOTS_REMOTE_DDS, THORNBOTS_FOXGLOVE). Robot defaults: remote DDS off, Foxglove on; sim, tests and agent containers: both off. The image's bashrc part takes effect on the next image build; dexec.sh covers agent containers now.
