Initial bugs and warnings

  1. Localization blocker: stationary drift above.
  2. Serial diagnostic blocker: 3/10 PINGs unanswered. Recurring NO DATA ... ~1000 ms warnings about every 180 s coincide with rf2o's missing odom-at-scan-time fallback. Correlation, not diagnosis; firmware unmatched.
  3. Camera delivery unresolved: raw rates below 60 fps, metadata gaps and repeated RealSense libusb EAGAIN warnings. Transport versus source loss needs isolation.
  4. Engine portability: TensorRT cross-device warning despite successful load; validate or rebuild for this Jetson if the model workflow requires.
  5. Transient TF drops recovered. One preboot CRC8 mismatch at 19:31:04 EDT (counters read live, not retained); duplicate rf2o logger name and Foxglove TensorList schema warning remain.
  6. Postboot SLAM serialization logged variable lidar range counts (for example 359 readings, expected 500). Saved-map impact untested; verify reload before map acceptance.

Initial sim-to-real differences and promotion

  • Hardware camera ran about 59.5 fps, not an exact 60 Hz; no Humble hardware FPS/latency baseline exists here.
  • Stationary drift and real UART stalls are not covered by sim's idealized odometry and serial timing; hardware failed this check although topics and TF were present.
  • A real armor plate gave depth and a valid track, but this does not validate calibrated depth or physical aiming.
  • Hosted firmware fixtures cannot establish controller-loss behavior.

Initial promotion assessment: no-go. Localization drift, serial loss/delay, raw-depth delivery, calibrated depth and matched-firmware acceptance remain open. The promotion decision is the user's; no main merge was performed.

Confirmed SLAM beam-count rejection / sim-to-real gap

SLAM rejects hardware scans because the beam count varies; still present after flash.
Repeated LaserRangeScan contains 356 range readings, expected 580 (343–359 seen). The observer got 1,335 scans of 340–361 beams, none 580, with angular increment 0.01715–0.01760 rad. In Karto 2.8.5 LaserRangeFinder::Validate that message is followed by return false, so these are rejected scans. Logs do not quantify all rejections or prove no map updates occurred. Fixed-beam sim scans do not exercise this. The suspected cause is angle_compensate false in thornbots_pkg/launch/auto.launch.py; that setting is under test. Map updates and saved-map reload on hardware are still to verify, and the rejection remains open here.

The saved analysis's NOT SCORED verdict predates the revised grades above. The original stack stayed active with NRestarts=1 and no manual restart.
