## Coverage limits and follow-up

E1/E2 were not run: their opponent paths cross field obstacles and the package
instructions mark those suites invalid. Real hardware, camera/YOLO detection,
STM32 timing, motor dynamics, boot calibration, and physical projectile exit
were not tested. No firmware was flashed.
The separate on-demand EKF ground-truth diagnostic was not run; no EKF or
rf2o parameters changed.

The Mac environment has neither CUDA nor `isaac_ros_nitros_image_type`, so
the NVIDIA perception front end and CUDA/VPI common libraries were not built.
An attempted build of the common Python utilities was blocked by their declared
`isaac_ros_common` build dependency, which requires CUDA/VPI; an initial direct
pytest invocation also lacked the installed `isaac_common_py` module. These
are environment/coverage limits, not a passing common-utility test result.
Robot startup service behavior was not exercised.

Standard-practice issues still visible: firmware compilation warns about
initializer order, unused parameters/variables, and equivalent EAGAIN/
EWOULDBLOCK comparisons. rf2o retains deprecated package.xml format 1.
The incomplete health-check criteria need follow-up; reject nonzero clock
synchronization timeouts manually when evaluating a run.

## Reproduce in a container terminal

Use a clean recursive checkout of workspace `17ef198`. For historical
reproduction, keep each submodule at that revision's exact gitlink; checking
out a newer nightly branch head can change the test inputs. Initialize the
optional firmware and its nested dependencies. Build/test commands
below assume Jazzy dependencies, Gazebo, `scons`, and `g++-11` are installed.
Run each runtime suite sequentially with no existing stack.

```sh
cd /workspaces/isaac_ros-dev
git -C src submodule update --init --checkout firmware/MCBV3
git -C src/firmware/MCBV3 submodule update --init --recursive
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-select \
  dji_serial_bridge thornbots_pkg sentry_localization sim \
  rf2o_laser_odometry sllidar_ros2 roi_depth_query
src/sim/tools/build_mcb_firmware.sh
source install/setup.bash
colcon test --packages-select dji_serial_bridge thornbots_pkg \
  sentry_localization sim rf2o_laser_odometry sllidar_ros2 roi_depth_query
colcon test-result --verbose

ros2 launch sim shot_hit.launch.py log_dir:=/tmp/nightly-shot-hit
ros2 launch sim estimation.launch.py log_dir:=/tmp/nightly-estimation
# Optional diagnostic control, not the normal throughput run:
ros2 launch sim estimation.launch.py \
  real_time_factor:=1 only_stationary:=true log_dir:=/tmp/nightly-estimation-control
ros2 launch sim localization_tests.launch.py backend:=amcl use_rf2o:=true
```

Save each launch's console log and run `python3 src/sim/tools/check_bench_log.py
<log>` afterwards (include scenario logs for localization). Inspect pytest's
summary separately; ros2 launch and colcon test can return zero despite
underlying test failures. Full local logs and per-state/per-shot data are under
`/workspaces/isaac_ros-dev/nightly-validation-2026-10-06/` on the test machine.
